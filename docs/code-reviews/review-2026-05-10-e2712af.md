## Findings

### `apps/frontend/src/pages/GuideViewPage.tsx`

- **🟡 (New: AWD-L-32)** Lines 98–103 — PDF anchor click without DOM append  
  `anchor.click()` is called on a detached element (never appended to `document.body`). This
  works in Chrome and modern Safari but is technically unreliable in Firefox and some Android
  WebViews, which require the element to be in the live DOM before the synthetic click triggers
  a file download.  
  **Fix:** Append before click, then remove:
  ```ts
  document.body.appendChild(anchor)
  anchor.click()
  document.body.removeChild(anchor)
  URL.revokeObjectURL(url)
  ```

- **🟡 (New: AWD-L-33)** Lines 234–241 — `downloadError` banner has no dismiss button  
  Once the error banner appears it stays visible until the user clicks Download again (which
  clears it via `setDownloadError(null)`). A user who reads the error and decides not to retry
  must navigate away or reload to clear it — which is mildly confusing.  
  **Fix:** Add an `×` dismiss button inside the alert `<div>`:
  ```tsx
  <button
    onClick={() => setDownloadError(null)}
    aria-label="Dismiss error"
    className="ml-auto text-red-400 hover:text-red-600"
  >
    ✕
  </button>
  ```

- **🟢 (Reinforces existing AWD-L-25)** Line 108 — `err instanceof Error ? err.message : 'Unexpected error'`  
  Same inline ternary already tracked in AWD-L-25 (`getErrorMessage` utility). GuideViewPage.tsx
  should be added to the file list for that item; no new backlog entry required.
